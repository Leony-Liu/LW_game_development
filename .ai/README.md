# Codex 过程文件

`.ai/` 集中保存 Codex 专用的辅助脚本、生成快照和隔离自动化数据。仓库级协作契约仍是根目录 `AGENTS.md`；本文件仅说明文件归属与放置方式，不建立第二套全局指令。

| 路径 | 职责与维护方式 |
| --- | --- |
| `scripts/` | 维护并纳入版本控制的 Codex 专用过程脚本；不是玩法源码或通用项目工具 |
| `generated/` | 生成快照等产物，默认忽略；现有 `PROJECT_DUMP.md` 原样迁入，内容不会随源码自动更新 |
| `runtime/` | 隔离的自动化用户数据、临时环境、日志、截图与验证证据，默认忽略；保留有用历史数据 |
| `tmp/` | 任务级探针、草稿和可丢弃中间文件，默认忽略；完成任务后清理新建的一次性文件 |

稳定项目工具 `tools/godot_cli.ps1` 保持原位，其 `APPDATA`、`LOCALAPPDATA`、`TEMP` 和 `TMP` 指向 `.ai/runtime/` 下的相应目录。Godot 管理的 `.godot/`、资源、场景及用户维护文件保持原位。隐藏目录 `.ai/` 不作为 Godot 资源目录使用；源码快照生成器也排除整个 `.ai/`，避免嵌入运行数据、备份或旧快照。

## 任务结束审查与历史文件保护

每项任务结束时必须执行 `AGENTS.md` 的清理审查，使用 `ACTIVE`、`TASK_TEMP`、`HISTORICAL_EVIDENCE`、`LEGACY_CANDIDATE`、`UNCERTAIN` 分类，并报告已处理内容和未决候选。

- `runtime/` 保存自动化运行状态、Godot CLI 隔离用户/临时数据、验证日志、历史验证证据和任务报告，不是通用可丢弃缓存。考虑删除前先检查实际内容、进程使用和归属；保护 AppData、Temp、存档及活动状态。
- `tmp/` 保存任务级临时探针、草稿和验证中间产物；本任务创建的一次性文件在验证完成后清理。历史文件不能仅因位于此目录就删除。
- `generated/` 保存生成快照等产物；提出删除前确认是否可重现。当前源码重新生成的快照未必能重现历史状态；不得覆盖用户维护或手工编辑的文件。
- `scripts/` 保存支持持续开发的过程助手，保留仍在使用的脚本。
- 历史任务目录必须逐文件检查用途、内容、引用、保留证据、过期中间输出和重复/替代关系，再提出有依据的删除或归档建议。没有文本引用不能单独证明无用。

历史文件的删除、移动、重命名和归档都必须等待负责人明确批准精确路径；整体任务批准或目录批准不代表批准其中全部文件。不确定文件原位保留。有用的既有日志、截图、报告和恢复备份优先保留；不得因为任务完成或文件较旧而清空目录。批准执行前再次检查文件内容、引用、活跃状态和是否变化；变化的候选须重新批准。当前任务的调查、分析、审计、验证及基线报告等默认属于过程产物，仅在负责人明确批准持久保留时才留在项目中；否则在最终回复交付必要结论与证据后，于任务完成前清理临时报告和执行记录。此规则不授权删除其他既有历史材料，具体遵守 `AGENTS.md`。

## 生成源码快照

在项目根目录执行（Windows 也可将 `python` 换为 `py -3`）：

```powershell
python .ai/scripts/build_godot_snapshot.py
```

默认项目根目录从脚本位置向上定位，不依赖终端当前目录；默认输出 `.ai/generated/PROJECT_DUMP.md`，相对输出路径以选定项目根目录为基准。显式项目目录、`-o` / `--output`、`--max-file-mb` 和 `--no-line-numbers` 保持可用。主动运行生成器会更新指定输出，生成前应保留需要留存的旧快照。快照只代表生成时的文件状态，不是测试结果或实时实现依据。
